# Phase 10 — Alt text

v2's third phase (ROADMAP §11, "Built in this order"), 2026-10-21. An image a tool returns is
described by the local model, on this computer, and the description is labelled as generated
wherever it is read or heard. Closes §4 pitfall 6.

**Status: complete.** Schema 903, Core 229, Inference 4 (with a model; two skip without one), UI 87 —
all green; the NVDA pass found one wording fix (§4).

## 1. The decision

**Described automatically as it arrives, with a setting to turn it off** — the developer's call,
against describing only on request. The description is the reason this audience has a model at all,
and asking for it every time is a keystroke per picture. The cost is processor time nobody asked for:
15–25 seconds a picture on the development machine, about 50 on an ordinary four-core laptop. So:

- **Settings, "Describe images with the local model as they arrive"**, on by default (`describeImages`).
- **Describe** — a button on every picture humcp can show, and <kbd>Ctrl+D</kbd> anywhere in a result
  (the picture the caret is on, or the only one). Shown with no model too: a button that appears only
  after a download is a feature nobody finds, and pressing it without one says where to get one.

## 2. What was built

- **`LocalModel.DescribeImageAsync`** (`Humcp.Inference`): the bytes as the server sent them, through
  GenAI's `MultiModalProcessor` and `Images.Load(byte[])` — nothing is written to disk. The request is
  the spike's (v2-llm-spike §4.1): kind first, only what is visible, "say so" rather than guess, under
  120 words. A 4,096-token cache, not the model's 262,144.
- **`ModelHost`**: the one loaded model the application shares, loaded on first use. The File menu's
  check and every description go through it, so there is never a second copy in memory. Removing the
  model awaits `UnloadAsync`, which lets a description in progress finish before the files go.
- **`ImageDescription`** (Core): every sentence, tested — "Generated by the local model, and it can be
  wrong:" before a word of the description; "Description of an image, PNG, 243.7 KB is ready, in the
  result. It is generated, so it can be wrong." as the announcement; the same hygiene as server text.
- **`ResultView`**: on each result, every picture's box says what will happen — describing, no model
  yet, or turned off — and with the setting on, the pictures are described one at a time, in order.
  Replacing the result, or closing its window, stops the rest. A second Describe on a described
  picture says where the description is rather than asking the same question again.
- **The UI suite's model store is an empty temporary folder** (`HUMCP_MODELS`), like its other three
  files: a model in the profile of whoever ran it would otherwise describe every picture the suite's
  tools return, and make what the image tests hear depend on the machine.

`IResultSummarizer` is still not an interface, for the reason `IToolSuggester` is not (§12): Phase 11's
summaries are the second implementation, and that is where its shape will be known.

## 3. Measured

- **The fixture**, `tests/fixtures/images/weather-gc-ca.png` (a Playwright screenshot of a Government
  of Canada forecast, captured for the spike): 1,012 tokens in, first word 15.3 s, finished in 25.7 s —
  "This is a screenshot of the Government of Canada's weather page for Toronto, Ontario. It shows
  current conditions: 15.3°C, sunny, 49% humidity…". Every number checked against the picture.
- **Through the app**, Playwright's own server: navigate to Wikipedia's *Cat*, take a screenshot. The
  description was ready 31 seconds after the result (the model's load included): the article's
  heading, its introduction, "a small image collage of cats", the timeline, the Light and Standard
  settings, the 25-years banner — and the time range "0.095 Ma", off by ten, exactly as the spike found
  for this page. The label in front of it is there for that reason.

## 4. The NVDA pass

Through the screen reader bridge (silent, *user* stance), from a tool form — so through the form's own
result view, the one less exercised:

| Check | Heard |
|---|---|
| The result | "Tool call complete. 11 lines of text, an image, PNG, 243.7 KB." |
| Ready, 31 s later | "Description of an image, PNG, 243.7 KB is ready, in the result. It is generated, so it can be wrong." |
| The picture's box | "Image, PNG, 243.7 KB, part 2 of 2 … Generated by the local model, and it can be wrong: This is a screenshot of the Wikipedia page for 'Cat.'", then sentence by sentence with Say All |
| Describe | "Describe Image, PNG, 243.7 KB, button … Control plus D" |
| <kbd>Ctrl+D</kbd> on it again | "It is already described: the description is in the box under the picture." |

One fix: the box's help text still said "Everything the protocol says about this part", which stops
being true the moment a description is in it. It now says the description is there, labelled as
generated.

## 5. Not done here

- **The model stays loaded** once something has used it — a few gigabytes until humcp closes or the
  model is removed. Unloading after a quiet spell is worth measuring once summaries (Phase 11) give it
  a second user.
- **The details window (F1) does not include the description.** It is the record of what the server
  sent, and the description is not that.
