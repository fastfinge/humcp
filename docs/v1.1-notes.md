# humcp 1.1 — notes

What 1.1 changed is in `CHANGELOG.md`, and the rules it added are in ROADMAP §5 ("The other
direction") and the keyboard map. This file is the record of the NVDA pass, in the shape of the
phase notes before it.

## The pass

2026-10-19, driven through the screen reader MCP bridge (NVDA, Eloquence, `user` stance, silent),
against a scratch profile holding the fixture server, Open-Meteo and the MLB server.

**What was checked, and held:**

- Open-Meteo's Weather Forecast, from a filled-in form with hourly and daily variables. The
  announcement is *"Tool call complete. Result, 11 fields."* where 1.0 said *"1 line of text"*. F6
  lands on the tree and its help text says the server sent text and humcp read it as JSON. *"Hourly,
  table, 168 rows, 3 columns"* opens with Enter into a grid whose rows read *"2026-10-20T01:00, 11.8,
  0"*, with *"Temperature 2 m"* and *"Precipitation"* as column headers. "2 m" is spoken as "2 m";
  acceptable, and it is what NameHumanizer does with every such name.
- MLB's Get Tracked Teams: *"Tracked Teams, table, 1 row, 8 columns"*, the title line become the
  table's name.
- F2 on a list of choices (the forecast's Daily) and on a list of text (a server's environment
  variables), and the Edit button. The window is named for the entry, the caret lands at the end
  of a text entry, Enter closes it, the caret returns to where it was, and the list says the new
  value. The saved `servers.json` held the new value.

## Defects found by ear, none of them seen by the suite

1. **The entry window called its field "Item".** An item schema has no name of its own, so
   FormBuilder calls it "Item", and an entry opened on its own was announced as *"Item edit"*, with
   none of the list's help. Entries are now named for their list and carry its description when the
   item has none (`ListFieldState.Entry`).
2. **Closing a humcp window could put the user in another application.** After closing the forecast
   form, and again after saving a server's settings, Windows activated the terminal humcp had been
   started from. Nothing was said; the next keystroke went to another program. A tracked window now
   activates its owner while it is still the active window (`WindowManager.Track`, on `Closing`),
   because once it has gone the foreground is no longer humcp's to give. Re-checked: Escape on a
   form lands on its tree item, and a save says *"Saved test. Connecting."* and lands on the tree.
   Probably as old as Phase 3; it needs a window humcp did not open to have been in front before it,
   which no automated test arranges.

## Noticed, not changed

- **A grid does not carry the "read as JSON" sentence.** The tree's help text has it; a result that
  is a table at its root goes straight to the grid, whose help text is about arrows. The F1 text
  still says what the server sent.
- **A grid cell's value is spoken twice** (*"12.4 12.4 selected"*), and the first arrow in a grid
  window re-announces the window chain. Both are the Phase 4 grid's, not 1.1's.
- **Saving a server's settings takes about six seconds** before anything is said. The save waits for
  the server to be stopped and started again.
